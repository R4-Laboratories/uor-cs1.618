# cs1.618 in the Prism ecosystem

The shared address bar used by `afflom/me` and Verdant reads the canonical Prism registry. cs1.618 now uses that same `<prism-frame>` component. Type an app name in the bar to discover other registered apps; the person icon uses the shared Stitch Prism identity framework. The bar is available in the lobby and pause menu and hides during active mouse-look gameplay.

## Discovery and publication

`public/app.json` names the app, its repository and public game URL. `public/app.holo` is a real PrismPM-generated HOLO v4 archive. After Pages succeeds, `Register app in Prism ecosystem` obtains a repository-bound GitHub OIDC token with audience `prism-registry`, checks the served Holo matches the checkout, and posts its actual fingerprint to `https://registry.uor.foundation/prism/register`. No API-key secret is needed. The same registration protocol is used by Me's `bootstrap/register.mjs`.

A successful registration is not yet a listing: the registry indexer fetches and validates the app and its examples. The retained registration report distinguishes `registered-awaiting-index` and `listed`. The canonical bar verifies the SHA-256 of the registry's index snapshot before displaying entries. The registration workflow also runs every six hours and can be dispatched manually. Failure is reported rather than silently ignored.

The canonical frame is an unchanged published module from `UOR-Foundation/template`, with exact source revision, URL and SHA-256 in `model/prism-frame.json`. The client checks that hash before importing it. Its own optional panels are also content-addressed by the upstream frame. The associated upstream licenses ship alongside it.

## What the Holo contains

The `cs1.618` Holo is the identity-admission component: `origin fresh signature consent`, each `pass` or `fail`. It returns `allow` only when all four observations pass; malformed requests are refused. All 16 combinations and the generated acceptance examples are checked through `prism-code@0.7.2`, the actual Holo loader. The browser pins the compiled archive hash and uses the guest before exporting a public identity handoff. No handwritten fallback decides admission.

The portable component does **not** contain the whole WebGL shooter. Rendering, cryptography, IndexedDB and multiplayer are host responsibilities. `public/hologram/manifest.json` identifies the game entry point, compiled artifacts, hashes and host requirements; `base` resolves relative to that manifest. Downloading the Holo into a compatible loader runs the policy; opening the registry entry's live URL runs the game. The existing round and evolution Holos remain separately available.

Reproduce the source with `node scripts/generate-identity.mjs`, then run `PRISM_PROJECT=identity npm run prism:verify`. Regeneration changes the source lock and artifact identities; only copy an exact successful build, update `model/hologram-policy.json`, deliberately record artifacts, and regenerate `node scripts/hologram-manifest.mjs`. See [proof repair](proof-audit.md) for the explicit upstream verifier repair and unchanged artifact rejection checks.

## Identity and explicit linking

The [identity page](https://r4-laboratories.github.io/uor-cs1.618/identity.html) imports byte-pinned, unchanged cryptographic code from Stitch, Me and the canonical template. `model/hologram-vendor.json` records every file and license source, and verification rejects changed or extra vendored files.

- **Stitch identity:** the kappa of a signed genesis record. Nonextractable signing keys and the session live in this origin's IndexedDB. A new identity is created only on a click. Its id persists across reloads. Storage loss remains storage loss; this is not a backup service.
- **Device linking:** the actual Stitch link-offer/request/response protocol, with a five-minute offer, single-use acceptance and six-digit user confirmation. The page supports manual transfer over a channel the person trusts. Device linking does not publish to Stitch's relay. Public browser hosting separately publishes the signed listing described below. A browser with another identity refuses to overwrite it silently.
- **Shared Prism identity:** the current canonical frame uses Stitch’s `prism/session/1` signed delegation. Use its person icon to create or link the identity used by Me, then choose **Bind shared Prism identity**. The adapter checks the real current-frame delegation and signs an explicit mapping with both its delegated key and the game’s local device key. The two ids remain distinct until explicitly linked. Legacy Me `prism/identity/1` passkey delegations are separately supported, not assumed to be the current frame format.
- **Sharing:** downloads happen only after an explicit button click and Holo admission. Public proofs contain a stable id, public records and signatures, never private keys or Me's private content. They are fresh handoff proofs (60-second verification window), not permanent authorization tokens.

Identity does not give a player host privileges, money, damage authority or administrative access. Existing multiplayer transport remains WebRTC/PeerJS with optional dedicated WebSocket hosting; importing Stitch identity does not replace the game transport or promise distributed durable storage.

Offline checks can reject only revocations supplied in the checked log or trusted account-key set. They do not magically learn withheld revocations, prove hardware key protection, or prove a human's real-world identity. The legacy passkey account protocol lacks an issuance timestamp; the adapter bounds remaining lifetime and requires expiration within seven days of the signed binding. Tests use real current-frame Stitch signatures and synthetic legacy WebAuthn fixtures. Browser tests use an isolated test identity, never a private user account.

## Checks

`npm run verify` checks vendor custody, host-manifest integrity, all runtime tests, type checking/build and compiled artifacts. `npm run test:identity-browser` checks the actual frame, Holo loading, IndexedDB persistence, wrong-code refusal, linking two isolated browser contexts explicit public-proof download, and binding a real current-frame account. Every future autonomous promotion also runs this browser gate.


## Public browser matches

Creating a browser room defaults to **Public**. The disclosure beside that choice explains that its invitation and host public Prism identity are published to the hosted `https://ntfy.sh` relay using the unchanged, pinned Stitch `createRelayBus`. The explicit create action loads the current origin-local identity, or creates and persists one if absent. **Private** publishes nothing; its invitation can be shared directly. TURN credentials, private device keys, and shared-frame/Me session data are never included in either listing.

A signed listing binds app origin, game protocol, host Prism, room/token, Meridian map, callsign, human occupancy, capacity and signaling endpoint. Public discovery accepts PeerJS Cloud and same-origin PeerServers only; other custom signaling services require private invitations. Listings last at most 45 seconds and refresh every 20 seconds while the host runs. Polling checks the relay every 10 seconds, with manual refresh available. Normal leave publishes a signed withdrawal; crashes and failed withdrawals rely on expiry. Browser background throttling can cause a listing to expire while its peer room still exists.

The directory verifies shape, origin, freshness and actual Stitch signatures, then passes the four observed admission facts to the compiled identity Holo. Public publication consent is the signed `visibility: public` declaration made after the hosting choice. Discovery joins pin the listing's Prism and require a fresh signed challenge that binds the exact room/token, signaling endpoint, host PeerJS id and guest PeerJS id. The guest sends `join` only after this proof passes the compiled policy; any gameplay packet arriving earlier closes the connection. Direct invitation joins keep their existing bearer-token behavior.

The local directory holds at most 64 visible rooms and 128 lease/tombstone entries, limits concurrent signature checks to four, and processes at most 256 reassembled records per poll. Identity proofs remain bounded to 128 KiB and 32 public records. HTTP reads are bounded to 2 MiB and eight seconds. These bounds and signatures do not make the open relay resistant to identity spam or guarantee availability. Relay acknowledgment is explicitly labeled as acknowledgment, not delivery. Relay errors leave direct invitations available. Offline identity verification still cannot learn withheld revocations.

`npm run test:discovery-browser` tests two isolated browser contexts, production game code, real compiled policy and real WebRTC through a local PeerServer. Only the external ntfy HTTP boundary is intercepted for repeatability: actual upstream multi-frame publication/reassembly and actual signatures remain in the test. It covers discovery admission, normal withdrawal, private hosting and outage fallback. This is evidence for protocol behavior, not a guarantee about public ntfy availability or TURN reachability.

## Immutable shared-frame delivery

The pinned canonical frame and identity code are unchanged. Its externally hosted panels URL disappeared, so this app retains the exact two companion modules recovered from the pinned source and locked publisher. [Recovery and review](evidence/stitch-modern/prism-frame-dependency-report.md) document their custody. A narrowly scoped Service Worker verifies and supplies only those exact dependency GETs; it never caches or handles app navigation, game scripts or engine Wasm. Startup requires secure Service Worker control and a matching dependency map; missing/corrupt bytes or a conflicting worker at this same application scope visibly disable the shared frame. Existing cryptographic and compiled-policy admission checks remain mandatory.

## Private career record

Open **Career record** in the lobby to see lifetime kills, deaths and K/D. Multiplayer and local practice have independent totals. A multiplayer room with bots counts as multiplayer. At join, the client verifies a fresh signature from the selected Prism identity. Automatic prefers the local game identity if one was created or linked and otherwise uses a signed-in address bar identity. The profile selector also lets you choose either identity explicitly. Guests can play immediately. The Prism ID and career totals stay off the game transport. Each connection retains its identity for its duration. Rejoin after changing accounts.

The authoritative self snapshot includes an opaque score seat and cumulative kills and deaths for that seat. Those totals span scoreboard resets. A new connection gets a fresh seat. A short write-ahead checkpoint recovers interruptions during page navigation. The local writer keeps the greatest observed totals per seat inside an IndexedDB transaction, so repeated, delayed and missing intermediate snapshots, simultaneous tabs and repeated imports do not add the same score twice. The host decides who scored. These private records describe what the client observed from that host. They do not certify the host's fairness or provide a globally ranked leaderboard.

The pinned Prism frame supplies signing and device linking. Progress lives in this browser’s site storage. Where available, **Keep scores in browser storage** requests persistent storage against automatic eviction. The browser decides whether to grant it. To move it, download a signed career backup from the identity page, link or recover the same Prism ID on the destination and merge the file there. Export from the same game origin that you will restore on. A single backup contains the public Prism ID, the contributing seat counts, the signing proof and the public verification records. It excludes private keys, names, rivals and room invitations. The importer checks who signed and checks all scores before a single atomic merge. Newer progress on either device is retained. Link an additional device or save the shared identity recovery kit before erasing the last copy of a signing key. A score file alone cannot recover the identity. Back up again after playing to include newer scores.
