# Task2a0 scoped tracing review

2026-11-17. **READY at design level for the specified tracing addition**, subject to the existing repaired Task1 PASS, frozen provenance, current resource measurements, parent execution authorization and exclusive slot. This review covers `task-2a0-tracing-ruling.md` and the relevant a0 command/resource boundary only. No code, tests, compiler invocation, network, subagents or source/index changes; only this report was written.

Wrapping the one exact rustc command with the measured installed strace and `-f --always-show-pid -q -v --kill-on-exit -e trace=process -s 65536 --` addresses the stated gap: child creation and exec/exit events are recorded through tracing rather than inferred from100ms `/proc` samples. The wrapper launches only the owned subtree, preserves the existing rustc argv/env/cwd, attaches to no existing task, and creates no second compiler/dependency build. The ruling reports an actual small parent-owned trace probe; this review does not represent that probe as compiler execution or independently rerun it.

The acceptance condition is appropriately fail-closed: reconstruct PID lineage and successful versus failed exec transitions, pair unfinished/resumed records, and reject truncated, unknown or incomplete attribution. The65536 string limit is a recording bound, not permission to treat an ellipsis as complete argv. Traced executable paths remain claims to compare with measured held tool identities and pre/post provenance; strace output is not an independent source/acquisition authority. Existing rlib/sysroot/dependency checks are still required, since process-only tracing does not establish file-input closure.

Raw process records share the already enumerated link stderr stream, and every byte—including tracer output—counts against the existing8MiB aggregate stream limit. Implementation must retain that raw stream and accept attribution only when it can unambiguously recognize complete tracer records among ordinary compiler/linker diagnostics; ambiguity refuses. It must never drop trace lines, silently truncate a record, create an unbounded trace file, or increase the cap to make attribution pass. The existing bounded-pipe owner, deadline and failure-retention rules cover trace growth/backpressure.

The existing180s link deadline,128MiB aggregate owned growth,2GiB owned-process-tree RSS and8GiB disk floor remain controlling; tracer runtime/resource usage belongs to the same owned operation. Tracer/runtime identities enter tools-before/after. `/proc` still monitors live resources and is not used to fill missing historical events.

Cleanup ownership is unchanged and sufficiently explicit for this component design: stop the owned process group, wait/reap the direct tracer process, and require terminal accounting/no surviving owned descendants before publishing success. The trace must reconcile every observed child/thread creation to completion or an explicit failed operation. `--kill-on-exit` is defense if the tracer terminates, not evidence by itself that cleanup succeeded. No detach/daemonize or cleanup of unrelated tasks is permitted. An interrupted/incomplete trace produces retained failure, never a successful acquisition index.

No new authority, unbounded-log allowance or reaping exemption is introduced. The addition is confined to unadmitted a0 snapshot-fixture acquisition. Actual helper/link execution, attribution-parser correctness, complete trace and cleanup evidence remain implementation/execution obligations; Task3 production custody and later a1/integration gates remain open.
