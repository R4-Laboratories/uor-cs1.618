## Findings

### P1 — Qualify the new proof constants against legal source names

**Locations:** `src/backend/constructive_nat/emit.rs:135`, `:163`, `:172`; existing name-admission context `src/ir/semantic.rs:3154`, `:3320`, `:3811`.

The emitter writes `of_decide_eq_true` and `congrArg` as bare names. Both are legal source identifiers and neither is in `BACKEND_BARE_NAMES`, so the unchanged binder/declaration checks allow them. The constructive input checker also accepts them as ordinary Nat binders. A selected theorem with parameter `of_decide_eq_true : Nat` and proposition `of_decide_eq_true <= 3 -> of_decide_eq_true <= 4` follows Recipe A and reaches the emitted LiteralLE expression `of_decide_eq_true (Eq.refl true)`. That reference resolves to the Nat parameter, so the generated Lean applies a Nat as a function. Likewise, a used Nat binder named `congrArg` captures equality transport/normalization applications. A legal declaration of either bare name in the generated namespace creates the analogous collision. This violates the required generic alpha-indexed behavior: a legal renaming changes successful proof emission into invalid Lean, rather than a checked constructive proof or registered pre-emission refusal.

**Required repair:** root-qualify the approved Init constants in this selected emitter (and audit its remaining constant references for the same issue), preserving existing source-language acceptance. Do not solve this by adding broad parser/IR exclusions. Add authored-source regressions with the two used parameter names and a same-namespace declaration collision; run their generated proofs through the actual pinned Lean/kernel/empty-axiom path within the authorized component validation scope.

**Existing coverage:** generic renamed/reordered fixtures use ordinary names; the 14 focused tests do not exercise these newly referenced bare constant spellings. This is a static finding from accepted-name rules and emitted expressions, not a claimed new executed failure.

### P2 — Enforce the remaining cumulative byte budget before producing bytes

**Locations:** `src/backend/constructive_nat/emit.rs:5`–`:17`, `:112`; `src/backend/constructive_nat/mod.rs:169`–`:177`, `:189`–`:195`; `src/api.rs:508`–`:512`.

The per-theorem **1MiB proof cap** is checked before each append, but the **remaining original cumulative output budget** is not. `emit` receives `&Stage`, uses only its deadline, and can construct the full proof up to 1MiB even when the remaining shared allowance is zero; `compile_checked` calls `stage.charge(proof.len())` only afterward. A concrete boundary is a stage whose remaining allowance equals the certificate's serialized length: serialization consumes that allowance, then proof rendering still allocates/appends its entire result before refusing. No accepted output escapes the eventual check, but the required pre-expansion/pre-allocation limit has already been crossed.

The final artifact has the same sequencing problem relative to existing output accounting: `artifact(...)` fully serializes, decodes and checks it before `api.rs` compares its size plus `report_total` to the original project limit. The stage's own allowance does not account for those previously accumulated production reports. In addition, `canonical` gives its first writer the entire limit and only checks the canonical `to_file_bytes()` result after allocation; canonical framing adds the final LF, so a JSON body exactly filling the allowance constructs one extra byte before rejection.

**Required repair:** pass the remaining relevant allowance into each output producer. The proof writer must stop before append at `min(PROOF_BYTES, stage_remaining)` and maintain the same cumulative accounting across theorems/modules. Before final artifact serialization, constrain its writer by both the stage allowance and `max_total_source_bytes - report_total` (checked subtraction), retaining the original diagnostic meaning for that project limit. Reserve/check canonical framing, including LF, before constructing it. Preserve existing budgets; do not raise them or reset the stage.

**Existing coverage and missing regression:** `serialization_and_shared_stage_budgets_do_not_reset` (`tests.rs:355`) checks eventual refusal and a fully exhausted next compilation, while `proof_expansion_checks_before_growth` checks the independent 1MiB cap. Neither proves the partial remaining-stage case stops the proof writer before growth, or that a nearly exhausted existing `report_total` constrains artifact creation. Add focused exact-boundary tests for certificate-fits/proof-does-not, partial proof allowance, canonical body-plus-LF, and preexisting report bytes plus final certificate. Assert bounded writer growth/refusal before allocation/append, not only the final `Err`.
