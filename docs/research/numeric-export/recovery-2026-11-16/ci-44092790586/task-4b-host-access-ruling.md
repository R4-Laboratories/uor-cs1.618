# Host-access design ruling for fix round4

Ruling: permit at most the authenticated actual runner primary GID as an additional **process-wide** supplementary group in the host UID1000 child, only when held measurements of the fixed source/game access paths show it is necessary and sufficient for the supported POSIX access classes. This privilege is not confined by the kernel to the measured ancestor; record that scope honestly. The authorized work is the existing trusted, fixed host collector/preflight/budget operations on the ephemeral GitHub runner. It introduces no account/group/sudoers/ACL/ownership change, no caller-supplied GID/path/program, no secret environment forwarding and no source/SDK actor change. The existing primary UID/GID1000 and source current-owner/no-follow/private-file checks remain unchanged.

This explicitly supersedes the prior host design's Docker-group-only restriction for source-reading host operations. Source traversal and Docker access are separate roles: all six source-reading operations may receive the measured necessary runner primary GID; only the existing socket-using operations receive their measured socket GID. Deduplicate exact groups and verify actual child credentials. Control-only metadata/raw guards gain no source child or group transition. Do not inherit all runner groups, read arbitrary account group memberships, or choose extra groups from encountered files.

Before dropping credentials, root measures fixed actual path ancestry and required source/game leaves under the existing deadline: identities, owners, modes, supported ACL state and expected permission class. Use held no-follow identities and reject aliases/unsafe ancestry/unsupported ACLs. Bind the original partial.host_source to actual fixed source. If baseline source credentials already suffice, omit the extra group. The only additional candidate is trusted SUDO_GID, and mode evaluation must establish its necessity on the fixed required path(s). Actual dropped-child traversal and original source reader/readback remain mandatory; root or POSIX arithmetic cannot substitute for them.

A runner0700 ancestor or any unsupported/unreadable layout must refuse with bounded actual path/credential/socket diagnostics. No chmod/chown/ACL modifications to host ancestors, guessed group, root-mode source reader, retry, namespace fallback or changed source mount identity. A fixed namespace is a distinct future design only if actual evidence makes it necessary. The current repair does not assume the unlogged hosted mode is0750.

Preflight covers both source-owned prepared records and fixed runner-owned game authorities used by collection, plus ordinary-runner readability of fixed public devcontainer/cache build inputs after chown. Retain bounded structured diagnostics before early source read and through the failure artifact; do not hide identity observations in a string likely to truncate. Preserve real failure exits and nonacceptance state. Existing stream/metadata/combined caps, all phase deadlines, original source snapshot/pins and SDK gates are unchanged. Add restricted-ancestor real two-identity fixture support, with explicit local unavailability and actual hosted preflight as the cross-UID witness.

This ruling is a design proposal for independent targeted review before implementation. It is not a claim that the actual hosted access layout supports the group, that a privileged test has passed, or that SDK qualification succeeded.
