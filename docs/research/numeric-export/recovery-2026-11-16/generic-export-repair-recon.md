## NEXP-010b: preserve local fixed-width types through control flow

A destination-only patch cannot close this issue: fixed literals are rendered unsuffixed (`Lower.lean:491–496`, codegen:2537); fixed literal constructors reduce to their operands (`Lower.lean:556`); let, join and case binder types are discarded at683,685–723. `joins.rs:301,353` materializes jump arguments as untyped lets after expansion. This is why a return signature is not sufficient to type an earlier checked-method receiver.

Smallest coherent follow-on design is explicit, noncoercing fixed-value type metadata preserved through lowering, parsing, lexical normalization, join expansion and emission. Prefer one additive typed-expression/typed-binding mechanism over operation-specific default casts; a possible spelling is `(typed-value UInt16 expression)`, emitted as a single-evaluation Rust typed binding, not `as` conversion. Exact spelling and allowed type grammar remain a design decision, not an implemented contract. It must retain fixed scalar and needed Option payload types at local definitions and join/case boundaries, including continuation copies. Existing copy/borrow/eager-binding analyses and65536-node/128-depth budgets must traverse and preserve the new node, and any new generated temporary must enter naming hygiene.

Before selecting that representation, inspect actual LCNF for signed minimum and fixed `ofNat`/`ofInt` literals: blindly typing the constructor's original Nat operand can reject valid wrapped fixed literals or change semantics. Current bare `Negate` emits Rust unary minus (sourcecodegen:2683), so signed-minimum handling needs a real source/evaluation/native witness; no new runtime wrong-value bug was demonstrated by this read-only task. Out-of-domain literal forms may be explicitly refused in a bounded first candidate rather than assigned an invented wrapping/coercion rule.

Required tests: reproduce each observed E0689/E0282 shape before repair; literal-only checked receivers, negative receivers, joins called with different literal paths, shadowing and nested match payloads, signed minima and maxima, zero and width boundaries, and an eager checked failure whose value is discarded. Compare actual Lean/native/Wasm values and None/ComputeError channels, not just successful rustc. Closure of NEXP010 requires both conversion and local-type cases; do not mark it closed after only010a.

## NEXP-011: builtin Prod projection and ownership

Lowering correctly identifies declared fields (`Lower.lean:499–515`) and lowers `Prod` to Tuple (`751`); it excludes Prod from named type declarations. Constructor emission already creates Rust tuples. Generic projection emission (sourcecodegen:2808 / vendor:2836) instead uses `.fst`/`.snd`, and its unknown-field check only applies to named declarations.

Do not alter named record fields named fst/snd, reorder nested pairs, flatten tuples, or apply a string replacement to generated output. The actual packed `(UInt32,Int16)` witness must extract unchanged and compile/replay after the repair.

Component type must feed existing ownership logic. `ownership.rs:41` only resolves named projections, although the same module already resolves Prod constructors and tuple patterns. Additional affected sourcecodegen sites are expression_is_non_copy:740/768, borrowed projection logic:1075, returns_borrowed_projection:1593, projection_field_type:2108, list-valued projection:2188 and final render:2808. Renderer currently has no general lexical LocalTypes field; existing ownership walks carry scoped LocalTypes. Reuse/extend that explicit type recovery after lexical/join normalization rather than adding a second field-name-only table. Unknown receiver/component types must remain unknown/refused, never be presumed Copy.

Stage non-Copy/nested support separately if necessary. Scalar-only success is not generic closure: test tuples containing String/Bytes/named records/Option, projected values used twice or alongside the whole owner, borrowed and owned receivers, temporary tuples, aliases, shadowing, nested projections and joins.
