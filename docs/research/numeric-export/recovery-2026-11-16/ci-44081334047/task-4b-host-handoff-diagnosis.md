## Proposed smallest repair boundary

Use the existing fixed game driver, workflow and focused tests only. No new source API, probe, subject adapter, snapshot, action pin, SDK pin or broad trigger. Introduce an explicit host bridge with a closed operation set for image retention, qualification retention, the two setup-budget sites, and metadata/raw admission. It has three roles:

**A. Runner entry.** Runs as the actual Actions runner, captures actual uid/gid and validates its current game/workspace/control-file identity. It alone opens/appends GITHUB_OUTPUT. It launches a bounded, exact root command such as `sudo -n -- /usr/bin/python3 -I -B <fixed checked game driver> <closed privileged bridge operation>`. No `sudo -u`, `sudo -g`, `-E`, askpass, arbitrary program/path or user-supplied shell. Root execution of Python is a candidate strategy, not proven by mkdir/chown success: a bounded preflight of the exact bridge invocation must fail early and retain runner-owned diagnostic status if policy does not allow it. Do not rerun the expensive image job merely to discover another avoidable host boundary.

**B. Narrow privileged bridge and dropped child.** The privileged entry verifies root identity, actual invoking runner UID/GID (sudo-origin data joined to actual runner-owned paths/context), fixed game Git/code identity and fixed workspace. It inspects the real Docker socket's type/group; a child uses process-only `setgroups`/`setgid`/`setuid` to run as UID1000, primary GID1000, with only the actual socket group when that operation requires it. No passwd/group/sudoers edits. The child verifies actual dropped IDs/groups before accessing originals. Root must not replace UID1000 source validation with a permissive root read.

Authenticate and carry the actual first-step clock and narrowly required runner identity in a bounded typed internal context, not invented environment variables. Source/preparation game and original clock joins remain mandatory. Reset the dropped child's environment to the minimum fixed host tools/locale needed for Git and Docker inspection; do not carry ACTIONS runtime tokens, credentials, GITHUB_OUTPUT, general runner secrets or compiler overrides. Retain numeric identity/socket/control-path observations without dumping environment values. Root and child commands are fixed; no public generic privilege or execution API.

**C. Explicit export and control handoff.** UID1000 validates source/raw custody and produces bounded export copies and a closed handoff inventory in a private fixed ignored host-export area. These are export copies, not source originals. After child exit, the bridge validates their complete path/byte/hash inventory, no-follow/single-link/owned directory/file constraints, combined4GiB cap and metadata32MiB cap, then makes only those fixed export objects runner-owned under fixed `evidence/metadata-upload` and `evidence/raw-upload`. For raw data, prefer a validated same-filesystem atomic relocation of the already created collector raw **copies**, followed by descriptor-based owner transfer of only that enumerated tree. This avoids another up-to4GiB disk copy and preserves source original custody. Require same device and absent confined destination; fail incomplete on mismatch rather than silently falling back to an unbudgeted second copy. Record old retained-copy location → runner upload location explicitly. Metadata is small and can use fresh bounded copies. Do not recursively chmod/chown source or private original workspaces, open world-readable originals, follow aliases or trust whichever files survive a glob. Transfer errors remain incomplete and retain available runner-readable failure metadata.
