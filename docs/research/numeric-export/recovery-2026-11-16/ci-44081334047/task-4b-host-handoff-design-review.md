## Accepted design and implementation boundaries

**Fixed privilege entry.** Use only the reviewed fixed driver and a closed operation set. Authenticate actual sudo-origin UID/GID against the measured runner context and owned fixed workspace/control paths; supplied JSON alone cannot establish caller identity. The root entry must reject arbitrary program, path, target owner, command, shell or environment choices. The exact `sudo -n -- /usr/bin/python3 -I -B ...` preflight belongs before expensive source-image work and must exercise the same drop/export/runner-read/control route with bounded disposable bytes. A successful unrelated sudo command is not a substitute. Failure before root starts must still leave a small runner-owned status and preserve the real exit.

**Process credentials and authority.** The child clears/replaces supplementary groups before dropping primary GID and UID to1000, adding only the measured socket group for operations that actually inspect Docker. It checks actual resulting credentials. No account/group/sudoers changes and no root relaxation of original `regular()`/`directory()` checks are admitted. Pass only the bounded typed internal context and required communication descriptors; close other inherited descriptors so a root-open handle does not silently bypass the credential drop. The child receives no GITHUB_OUTPUT, Actions tokens or general runner environment. Root filesystem operations are confined to validated export/control objects; original source validation stays in the UID1000 process.

**One export transition.** The proposed same-device relocation concerns only the collector's already-retained raw copies. Original source and private capture/replay outputs retain their identity, ownership, mode and bytes. Require an absent fixed destination without replacement, complete held inventory and no-follow/single-link checks, then transfer only the enumerated objects through checked descriptors. Do not fall back to another unbudgeted raw copy or recursive source chmod/chown. Include the relocation mapping and handoff/status records in the existing byte accounting. An interrupted owner transfer leaves a partial, non-uploadable export; root readability or a partially present destination cannot set raw_safe.

**Actual runner admission.** Before either export is uploadable, the ordinary runner must traverse, enumerate and read/hash the exact exported inventory under its real credentials. Root's success is insufficient. The runner alone opens GITHUB_OUTPUT, retaining its ownership and mode, and reconstructs only the allowed bounded integer/Boolean lines from a closed typed result. Valid controls or safely retained failure artifacts must never replace a failed child/bridge exit with success.

**Later guards are control-only.** A completed relocation is a one-time handoff. Metadata/raw budget guards subsequently use the authenticated persistent clock and fixed handoff state; they do not rerun source collection, reopen transferred files through the UID1000 reader, relocate raw again, or recreate a success marker from whatever remains. An occupied destination, mismatched clock, partial transfer or stale control record refuses admission. Fresh small failure records remain runner-owned. Already uploaded metadata is evidence of the recorded collection/export state, not proof that the subsequent raw upload completed; final review must still require the actual raw artifact and genuine workflow/action outcomes.

**Deadline enforcement includes privileged work.** The diagnosis's bounded-root/child requirement must be implemented by the privileged supervisor as well as the runner/Actions timeout. A normal runner timeout alone cannot establish retirement of a UID0 worker. The privileged supervisor must terminate/reap its owned child on expiry and stop further handoff mutations; timeout must not leave a background privileged exporter continuing after the step. Root entry, child work, inventory checks, relocation/ownership transfer and runner verification all consume the existing phase allowance. Preserve the same seven-minute source/one-minute host/one-minute metadata/one-minute raw allocation, five-second guard bound and persistent absolute collection/job deadlines. No late guard may create a new clock or repeat a large export.

These points specify the existing diagnosis's narrow authority, complete handoff, nonrenewal and timeout requirements; they do not request a general privilege framework, a new source API or additional actors.
