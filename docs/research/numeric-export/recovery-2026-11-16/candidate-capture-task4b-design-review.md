## Concrete finding and adopted correction

**B1 — the 60-minute reservation does not include the outer OC10 harness build.** Interfaces lines 82–84 reserve 60 min for the genuine Cargo command, with setup/two builds/components consuming up to 50 min and collection 10 min. However, source `crates/conformance/src/cases/mod.rs:760–770` passes 3600000 ms to the Node test runner, and `node_suite.rs:274–290` starts that timing only after the Rust harness exists. The inner owning test separately has 3500000 ms (`tests/publication-context-linkage/owner.test.mjs:4–6`). Neither bound covers the preceding Cargo integration-test compilation. Both proposed qualification subject builds are `--lib --no-run` in independent fresh targets (interfaces lines31–40; original `capture-owner.mjs:71–105`), so they do not prepare `--test conformance` in the eventual outer command's target. At the stated maximum 50 min setup + 240 min scenarios, only 70 min remain, already assigned to 60 min Node and 10 min collection; compilation/startup/validation has no allowance.

Smallest correction: include preparation of the exact original `repo-conformance --test conformance` harness in setup, using the restored source, original offline compiler environment and one fixed owned target. A preparatory `cargo test --locked --offline -p repo-conformance --test conformance --no-run` (with bounded compiler JSON retention if needed) must use the same target/profile/configuration as the later original invocation. Retain actual emitted harness identity/compiler output and source pre/post custody; recheck the held source and artifact before dispatch. This harness is separate from both fresh Q1/Q2 capture subjects and from OC10's own fresh private capture build. It cannot substitute for either.

Keep the original genuine Cargo test invocation and 65 + 2 registered checks, both original Node bounds and every 2400s capture bound.
