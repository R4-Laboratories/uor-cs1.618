## Conclusion and actionable scope

**The new failure is a real incompatibility between the conditional capture owner's current-source identity requirement and the unchanged old SDK's source tree. It is not a missing one-file candidate transport list.** The owner transports a current test ELF plus source *measurements*, while requiring the corresponding source files to already exist byte-for-byte in the immutable SDK. It never transports candidate source bytes. `exporter/source.rs` is one concrete newly added file that makes that assumption impossible for d6.

This establishes a source/runtime-boundary integration omission; it does **not** establish that the new generator cannot execute with d6's unchanged tools or that its recipe must revert. The guest fails before receiving/executing the current ELF. To retain unchanged d6, the smallest coherent repair direction is an explicitly separate, source-owned and independently reviewed complete-source transport/capture contract, with separate source/ELF and immutable SDK identities. There is no existing supported switch to enable that path. Alternatively, the unchanged capture contract needs a separately identified development image containing matching current source; such an image cannot replace or be relabeled as unchanged-d6 coverage.

Do not copy the one file into `/opt/prismpm/share/conformance-root`, mount an overlay there, skip source rows, point to an arbitrary source directory, change the original d6 inventory/lock, delete the SDK marker, revert the Released generator frame, or relabel this original failure. ## Smallest coherent repair while preserving unchanged d6

A source-owned **test-only source-transport capture route** can preserve d6 as the immutable tool/oracle runtime, but it is a new explicit contract requiring design/implementation and independent review. Minimum obligations:

- Keep `/opt/prismpm/share/conformance-root`, `/opt/prismpm/share/inventory.json`, SDK installed marker, executable PATH/inventory, d6 distribution/config identity and existing producer acceptance policies unchanged. Retain the original image-owned capture route for its original matching-source scope; no silent fallback after equality refusal.
- Bind the actual fresh source commit/tree (or independently owned private source closure), complete canonical source inventory, recursive fixture closure, exact current ELF digest/listing/count and separate d6 inventory/config/distribution identities in a closed versioned descriptor. Transport the **full original measured source bytes and aliases** through a bounded canonical protocol into a fresh confined candidate-source area in the owned private volume. Do not narrow to a guessed runtime subset or omit newly added tracked archives to make comparison pass.
- Materialize/verify that candidate tree separately from the installed source root; reject traversal, extra/missing members, aliases escaping/chaining, unexpected hardlinks or mode changes, mutations during transfer/execution, short/trailing/overlong data and unmeasured authority. Any compiled-path alias must resolve to this explicitly candidate-bound tree under the new contract and be audited as such; it must not claim that d6 contains those bytes. Existing SDK-root paths remain the original image's paths.
- Introduce a separately bound guest transport owner/launcher rather than relaxing the original helper's image-equality guard. Merely editing the current helper causes parent `:842-846` to reject its mismatch with d6 before guest startup. Therefore the repair must explicitly establish how the new source-owned guest authority reaches/executes in the immutable runtime, with its own exact source/byte identity and qualified process supervision, rather than overlaying installed scripts or pretending an arbitrary helper was already image-owned. A sealed transport-owned bootstrap/guest executable is a possible design, not an already supported path.
- Execute the **same actual test ELF** and original exact unignored case, not a rebuilt SDK/controller/test binary; preserve the complete test inventory, fixed SDK discovery and original external oracles. Before/after checks must cover candidate source, original SDK root identity/metadata, ELF, fixture source and private execution authority. Keep bounded capture logs/products and failure handling.
- Preserve existing resources and custody: 2400-second outer budget including transport, 420-second retirement reserve, source/capture tree <=512MiB and <=100,000 rows, regular-file <=256MiB, separately sealed ELF <=1GiB, canonical protocol JSON <=32MiB, original stdout/stderr bounds, private volume >=10GiB free, no-network/read-only rootfs, UID1000, dropped capabilities, no-new-privileges and existing CPU/memory/PID/tmpfs policy. Preserve authenticated container/volume/nested-oracle retirement and original incomplete-volume retention on failure.
- Version/extend closed transport, response and retained-capture provenance deliberately so the compiled source/ELF identity and immutable runtime image/inventory/source-tree identity are distinct, truthful claims. Update owning controls and independent capture decoders/receipt consumers together. Include actual changed/missing/replaced source, ELF/helper substitution, malformed/partial source transfer, fixture-extra membership, mutation, timeout/failure and retirement controls, plus genuine complete execution.

This is the smallest direction compatible with the requirement to test current exact source in unchanged d6. It is larger than a one-path repair because the old contract intentionally equates source identity with image-owned source. It must not weaken production SDK inventory or source-binding guards.

Preserve that separation; a new input transport must not turn this test-only fixture binding into production SDK admission or rewrite the SDK lock to match new source.
