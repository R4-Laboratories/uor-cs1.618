# Autonomous game evolution

The user requests the Verdant Resonance self-improvement mechanism and LexLean-R4 continuous GitHub publication loop in cs1.618. This implementation adapts their bounded candidate generation, admission, strategy learning, provenance, rollback and explicit deployment dispatch. It does not claim an unrestricted AI programmer, autonomous invention of new games, or full formal verification.

Its browser generations are local OPFS source/Wasm artifacts; its scheduled certified tick validates modeled stages. R4 reference: Casey-allard/lexlean-r4@f1cd751e12a60cafc2a61599cbbb15034941ba10, engine.yml and deploy-watch.yml. Its workflow explicitly dispatches Pages after automated writes. Do not copy its force pushes, test-failure suppression or deletion of workflow history.

A scheduled hourly engine and manual dispatch propose bounded source projections from a versioned policy. The initial finite search space includes static-mesh batching by spatial cell and an equivalent spatial index for navigation candidate pairs. These are real source rewrites used by the live renderer and host simulation. A finite search can settle; no-change is an honest outcome. New human-authored strategy families can expand the frontier.

Admission uses a separate generated LexLean/Prism Wasm decision kernel over measured fidelity, benefit, bounds and check results. Its Boolean policy is finite and exhaustively tested. It is not a proof of the empirical measurements or whole game. Existing round kernel and game rules remain unchanged.

Rendering candidates are compared with unbatched original geometry from multiple fixed cameras. Geometry/material transforms, screenshots, draw calls and triangle work are measured; image similarity and a declared work proxy decide admission, not fabricated FPS or subjective beauty claims. Bot candidates must produce exactly the same graph and routes while examining fewer pairs. The renderer keeps original objects for runtime rollback if batching throws. Unrelated rules, protocol, tests, admission logic and workflows cannot be edited by the automatic proposer.

The engine learns bounded strategy priorities from measured attempts and retains an auditable history. It runs type/build/artifact checks, all Node tests, rendered gameplay and real WebRTC browser tests before an admitted source update may be published. A publish operation requires a clean starting checkout, matching base SHA, exact allowed paths, and hash-matching tested outputs. Concurrent main changes abort; never force push or rebase tested changes without retesting.

GitHub Actions publishes accepted source with its normal repository token and explicitly dispatches Pages. A watcher compares main, Pages workflow results and a served build stamp; it dispatches missing builds, retries a deployment-only transient once, and reports validation failures without bypassing gates. No automatic issue/comment messaging. Repository variable CS_EVOLUTION=off pauses future scheduled ticks. No external AI key, hidden network telemetry or browser GitHub credential is required.
