# Stitch matches and modern tactical gameplay

## Intent and decisions
Make public browser matches discoverable through the existing Prism identity and Stitch backbone, then improve objective clarity, bot tactics, presentation and sound. The user chose modern CS-style presentation/mechanics and public-by-default rooms with private invitations available. Continue autonomously under the session authorization; preserve original assets and existing engine/model architecture.

## Approach
Use the existing pinned Stitch Prism identity and relay bus to publish signed, short-lived room advertisements. Keep PeerJS/WebRTC for realtime authoritative matches. Compared with replacing gameplay transport with a store/relay, this preserves working latency and authoritative game rules. Compared with a new central match directory, this uses the requested identity plane and needs no new owned backend. The relay is still a hosted availability dependency, and restrictive networks can still require TURN.

## Discovery contract
A room listing binds the Prism host, fresh time, game protocol, map, room invitation, occupancy, and signaling endpoint. Public room creation explicitly discloses publication of the invitation and host public identity; private rooms publish nothing. Use the unchanged upstream createRelayBus, not a simulated directory. Bound records, bytes, rooms and pending verification. Expire listings within 45 seconds; refresh every 20 seconds while online. Verify signatures, app audience, freshness and shape before admission through the compiled identity Holo. A join from discovery pins that Prism and demands a fresh live signed challenge binding the invitation and transport before accepting gameplay. Reject tampering, expired/replayed advertisements, identity substitution and unsupported endpoints. Withdraw on normal close; leases handle crashes. Never publish device keys, TURN credentials or Me session data. Report relay failure honestly and retain private invitations as fallback. No requirement for a paid service or model provider.

## Modern gameplay increment
Keep the existing 5v5 economy, two sites, original Meridian layout, host-authoritative simulation and compiled round decisions. Establish regression evidence for carry/drop/pickup, legal and interrupted plant/defuse, defusal kits, countdown detonation, terminal outcomes and round reset. Give players persistent team-specific objective instructions, site/dropped bomb direction/distance, interaction progress and time remaining. Make the planted object visually readable and stable. Bots should coordinate one defuser, cover teammates, escort the carrier, use line of sight and controlled firing/reaction rather than omniscient instant fire. Bound and test any added tactical behavior; retain generated tactic program integration.

## Presentation increment
Improve original weapon silhouettes/material skins and visible reload/switch feedback, site labels/wayfinding, map surface detail and lighting within the existing collision envelopes. Add distinct reload, interaction, bomb pickup/drop, warning and round-result sound cues with spatial bomb sound. Preserve audio voice bounds, volume controls and performance modes. Use procedural original assets; no Counter-Strike asset extraction. Keep geometry/material disposal bounded and avoid new colliders without engine integration.

## Architecture and evidence
The LexLean/PrismPM round, evolution and identity guests stay mandatory. The four identity admission observations must correspond to real checks, not fabricated proof facts. New host adapters, discovery and presentation remain tested/open claims; no whole-game proof claim. Retain upstream byte custody and UORust Rust projection; update manifest documentation if runtime use changes. Acceptance requires unit and real-Wasm tests, two-browser discovery and WebRTC joins, all existing browser suites, build/artifact validation, and successful Pages publication. Release notes distinguish implemented behavior, tested behavior and external-service availability.
