## Decision

Add an explicit **test-only candidate-source route**, selected before capture, alongside the unchanged image-owned route. Preserve `scripts/conditional-capture-sdk.py` byte-for-byte for the original route, including its helper/source equality refusal. A new source-owned Python entry point imports its reusable bounded primitives from an authenticated copy; a small source-owned bootstrap reaches the unchanged image as exact inspected `python3 -I -B -c` argv. Stage the complete measured source tree, authority and exact ELF into a separately owned input volume; retire its sole writable staging actor; then mount that volume read-only at `/candidate-input` in the execution actor, alongside the original writable work volume. Execute the already sealed current ELF through a narrowly adapted source-owned candidate launcher and the existing complete supervisor closure. Do not build another controller/test ELF inside d6.

This is workable at the inspected extension seams. It has not been shown to pass the compiler/oracle work that the old source-equality guard prevented from starting. A genuine focused unchanged-d6 capture is the next acceptance experiment after implementation and independent review. An unchanged SDK is a tool/runtime identity, not a claim that it shipped the candidate source.

No production SDK admission, inventory, marker, lock, public capability, policy, runtime PATH or tool pin changes are needed. The original Rust receipt and original independent release/source-free/22-mutation checks remain mandatory and retain their meanings. Same-UID chmod or before/after hashing is insufficient: no writable candidate-source, authority or ELF alias may remain reachable during execution.

## Task2 implementation rulings: runtime inspection and protected source roots

The implementation exposed two concrete design conflicts. These rulings supersede earlier references to only two actors and the unrestricted legacy compiled-root grammar; all original SDK/tool pins, two named volumes, execution policies and numerical budgets remain binding.

1. Runtime inventory and image authority must be measured before constructing the descriptor-bound stage argv. Authorize one additional **never-started image-inspection actor**, created before staging under a distinct closed role, fresh owner token and actual inspected immutable image/config. It has no source/input/work-volume mount, Docker socket or network; rootfs is read-only, privileges/resources no weaker than the staging policy. Its fixed harmless entrypoint/argv never execute. Require actual created/never-started/PID0 state before each fixed image-file read. Suppress image-declared anonymous volumes with an explicit fixed tmpfs at the declared workspace destination, and inspect/refuse any unexpected volume/mount. Actual suppression remains a Task4 daemon qualification requirement. Read only the fixed original inventory/helper/launcher paths through authenticated bounded image-file retrieval. Remove the inspection actor and prove its absence before creating the stage actor; descriptor runtime observations must bind these actual bytes/config. No unmeasured fixture runtime can authorize stage launch.
2. There are now three actor identities but still exactly two process attachments (stage/execute) and two owned named volumes. Ordinary inspection retirement occurs inside the work budget before staging. The full failure reconciliation, including ambiguous inspection creation, remains at most18 daemon operations capped15s each plus two attachment waits capped35s each, clamped to the single2400s deadline with420s reserve. Do not add a per-actor budget, retries, or independent phase reset. The implementation must provide a finite call/accounting table covering all phases; if this cannot fit, return the concrete design conflict instead of widening limits. Only authenticated actors may be removed; uncertain/failed captures retain created owned volumes. Successful evidence binds inspection, stage and execution retirement truthfully, while preserving noncircular original capture receipt/tree semantics.
3. The candidate runtime route must refuse `/workspace/NAME` **before Docker creation**: its parent is the separately writable work volume. Keep the legacy route and Task1 general source-plan grammar unchanged. Runtime candidate roots are only admitted `/workspaces/NAME` or the exact private `/tmp/prismpm-publication-capture-.../source` grammar, with actual root-owned protected ancestors, root-owned sticky `/tmp` where applicable, no-follow checks and both read-only source views. A read-only leaf alone cannot authorize a writable compiled-root ancestor. The independent Task3 reader enforces the same candidate-route restriction. No symlink or mutable-parent exception is introduced.

Task2 response/envelope, focused controls and Task4 actual daemon probes must include these boundaries. The inspection role is source test infrastructure, not a new SDK/production authority or a claim of isolation from the privileged Docker daemon.

## Bootstrap, immutable input ownership and launch authority

The trust entry is the reviewed source-side parent and independently inspected immutable image, as it is for existing ELF transfer. The new route explicitly grants test execution authority to measured candidate bytes; it does not pretend that byte equality with caller data establishes production authority.

A **dedicated input volume plus short-lived staging actor** is the minimum concrete design that preserves the original read-only source property without privileged mount operations. The execution actor needs writable cache/build/output storage and cannot safely share a writable volume containing candidate source. An in-container chmod, symlink, same-UID directory owner, pre/post hash or holding an open descriptor does not prevent transient source rewriting. The read-only mount is mandatory.

1. Parent measures source/fixture inventories, actual ELF, full listing/count, bootstrap and fixed authority files. Hold source/ELF metadata identities as well as bytes; recheck before every send and at the end. The ELF remains the existing fresh source-owned subject. Git metadata, when present, is separate from source rows; no-Git private source uses existing outer source-owner closure.
2. Create separately labelled names for one input volume, one staging actor, one work volume and one execution actor, all bound to a fresh owner token, role and inspected immutable d6 config. The staging actor mounts **only** the input volume read-write at `/workspace`, using image volume initialization to retain UID1000 ownership. It has no Docker socket, no network, no extra host mount and no tools/source bind. All other resource restrictions remain no weaker than the original actor. The staging actor never executes the ELF, launcher or compiler; its purpose is bounded input construction.
3. Stage entrypoint is fixed `/usr/bin/python3`; argv is exactly `-I -B -c BOOTSTRAP_TEXT` followed by closed arguments: stage protocol version, bounded remaining seconds, descriptor SHA-256, and the fixed two Python module lengths/digests. Bootstrap text is the exact bounded UTF-8 source file (recommend maximum 32 KiB), not shell interpolation. Inspect `Config.Entrypoint`, `Config.Cmd`, environment and mount/resource policy before start; require exact argv equality. Parent independently reads installed inventory and original image helper/launcher through existing stopped-image `image_file`, retains their digests and actual equality comparisons. Legacy mode still requires its own equality.
4. Stage bootstrap verifies Python 3.12.3, closed argv, UID1000, new owned directories and original free-space requirement. Read exactly two fixed-order modules (legacy utility helper and candidate entry), each ≤1 MiB, using bounded select/read loops. Verify declared digest/length before exclusive creation; no arbitrary capsule paths, aliases, hardlinks or imports. Record the actual `-c` bytes from closed pinned-Python `sys.orig_argv`. Execute the authenticated candidate stage entry with `compile`/`exec` in the **same PID**, explicit namespace and `__file__`; preserve stdin/stdout and the original absolute deadline. It imports the utility module by exact authenticated path, not ambient module search.
5. Candidate stage entry reads/verifies descriptor and complete source/ELF protocol, joins capsule/bootstrap bytes to exact source rows, and creates `candidate-source/`, `authority/`, `current-test-elf` and canonical input descriptor/manifest at volume root. Candidate source does not include these framing files as invented source members. Seal normalized modes as defense in depth, verify exact complete readback, return a bounded stage-admission record and exit. Stage stdin must have reached actual EOF before admission; trailing source input cannot trigger any ELF execution.
6. Parent verifies actual stage response/exit/stream exhaustion, then **removes and proves absence of the staging actor before creating execution actor**. Authenticate stage removal by token + role + image + exact ID/name. Enumerate containers referencing the input volume and refuse any additional owner or writable mount. No parked staging actor, second writer, or writable source alias may survive. Source volume content is not rebuilt or transformed between these phases.
7. Execution actor mounts the input volume read-only at fixed `/candidate-input`, also mounts exactly its `candidate-source` subdirectory read-only at the admitted compiled source root, and mounts the original new work volume read-write at `/workspace`, plus the original Docker socket. Inspect exact `Mounts` including `RW=false` for input and `RW=true` for work, exact volume names/destinations, only the one fixed `volume-subpath=candidate-source` mount at the exact admitted compiled root, no other subpath/alternate bind/anonymous extra mount, entrypoint/argv and all resource fields. The source volume must have only this admitted execution actor reference and both of its mounts must be read-only. `/opt`, SDK/tool paths, `/usr` and rootfs are never volume destinations. The compiled root is a separately inspected mountpoint, not a same-UID mutable symlink.
8. Execution bootstrap is the same measured `-c` source with a closed execute mode, descriptor hash and remaining deadline. It verifies the mounted descriptor hash and fixed authority capsule before same-PID entry to the candidate guest. Guest imports authenticated immutable utility bytes, verifies the complete read-only input tree and joins all authority/source/ELF measurements again before listing or executing the ELF, and creates only work/cache/output directories in the writable work volume. No candidate source, helper, supervisor or ELF is copied there. It invokes candidate launcher from `/candidate-input/candidate-source/scripts/conditional-capture-candidate-command.mjs`, which executes only `/candidate-input/current-test-elf`.

Python `-c`, exact Docker exec-form argv and read-only named volume/subpath mounts are concrete platform mechanisms, not an existing application switch. Source pins Docker CLI 28.4.0 (`sdk/Dockerfile:35`); the host daemon is separate, so the qualifier must inspect its API/version and actually prove `volume-subpath` support before relying on it. An incompatible daemon is a precise infrastructure prerequisite failure, not a reason to substitute a writable symlink. First actual d6 qualification must prove this stage/retire/mount sequence and actual read-only enforcement. Any inability to create the fixed mount destinations or satisfy original image initialization/ownership is a measured blocker, not justification for chmod-only fallback.

The Docker socket remains available only to the execution actor for original oracles. The guest process could therefore theoretically ask a privileged daemon to remount a volume; neither the original architecture nor this proposal isolates a malicious controller from that socket. The source transport contract admits only its measured supervisor/controller and unchanged oracle ownership code, inspects admitted actor references, and claims no writable source path in the admitted execution filesystem. Protection against a malicious daemon/host or deliberate new socket-mediated source writer would require removing/proxying daemon authority and redesigning original oracles, outside this smallest route. Do not claim a stronger threat boundary.

If builder policy forbids any source-owned Python inside d6 or any separately scoped read-only input mount, unchanged SDK plus changed exact source is infeasible under the old contract. No existing hook can install matching source while preserving the original source equality and rootfs; a separately identified development image is then required.

## Closed input protocol and complete source materialization

Use a distinct schema, e.g. `prismpm/conditional-candidate-capture-input/1`; do not silently widen the old unversioned descriptor. Closed top-level fields cover:

- original `source_root`, complete `source`, `fixture_inputs`, exact ELF bytes/hash/listing/count and remaining time;
- explicit `route`, source selection kind (tracked/private), source inventory digest, and union/materialized inventory digest;
- authority measurements for bootstrap, entry, utility helper, launcher and both supervisors, with fixed paths;
- actual SDK distribution, local config digest, OS/architecture, independently captured inventory digest and original image helper/launcher measurements;
- an optional **typed source-owner identity** (Git commit/tree measured from Git, or private inventory owner), never conflated with the modeled fixture's source URI/revision.

Source measurement first returns a closed source-input plan. An explicit binding operation adds the independently inspected runtime observations and produces the full closed capture descriptor before bootstrap. An unbound source plan is not stage input; null, inferred or fabricated runtime observations are forbidden. Component tests may use explicitly labeled structural fixtures but cannot claim runtime qualification.

Keep image config identity separate from distribution/index digest. The parent, not the guest's environment string, observes and binds the actual container image. No arbitrary root, arbitrary launcher, extra environment, alternative inventory path or user-defined authority module is admitted.

New-route canonical framing uses the unchanged Python `encoded` semantics: sorted object keys, compact JSON, ASCII escapes (including surrogate pairs for non-BMP characters), and exactly one final LF. Source/union row order is lexicographic UTF-8 byte order; reject non-scalar Unicode paths. The independent JS reader must implement that exact framing rather than hash ordinary `JSON.stringify` output, and normalize existing Map iteration order explicitly. Pin cross-language vectors containing both BMP and non-BMP path names.

After the two bootstrap modules, send: canonical descriptor line; all regular source bodies in canonical inventory order; exact sealed ELF body; canonical closed `inputs-complete` marker binding the descriptor and transfer manifest; then actual stdin EOF. Stage responds only after EOF and full verification. Source records describe directories, files (size/hash/executable) and relative aliases. Directory/link bytes are represented by their rows, not a tar header. The regular body is sent once per materialized path, including newly added archives and all exporter files.

Materialized inventory is the conflict-checked union of the original `source` and separately recursively measured `fixture_inputs`. For matching paths every row must agree. This preserves recursively consumed files even in a Git checkout with additional fixture members; it does not discard or mislabel them as tracked. For the usual private source closure the union equals source. Validate fixture closure independently against the materialized tree, including extra-member refusal. Preserve the original source list in evidence, rather than silently substituting the union for the tracked-source claim.

Strengthen only the new protocol's row decoder: canonical sorted paths, unique rows, every ancestor explicitly a directory, every link resolves directly to a measured regular file/directory, no link chain or link ancestor, no root escape, no special file, no unexpected hardlink, no absolute/backslash/control path. Inventory validation happens before file creation. Normalize owned directories to 0500 after construction, regular files to 0400/0500 according to original executable classification; do not grant execution based on a filename. Preserve relative alias target text. Require exact complete recursive readback with **no top-level exclusions** inside candidate-source; the source selection exclusions were already made by the original source owner.

Input volume layout is fixed: `authority/`, `candidate-source/`, `current-test-elf` and bounded descriptor/manifest files, all later visible only through `/candidate-input`. Work volume layout is `/workspace/conditional-capture/{capture,tmp,cargo,elan}` plus bounded command-result/stream files. Each destination must be new. Descriptor limits apply before allocation; stream large bodies to exclusive files in bounded chunks and hash while writing, avoiding an extra tree-sized memory copy. The original ELF allowance remains separate. Partial trees never become executable authority or success.

Bind the compiled source root with the fixed **read-only volume-subpath mount**, not a runtime-created symlink. A symlink in same-UID writable `/tmp` or `/workspace` could be retargeted transiently even when its intended target is read-only. Reuse `alias_root` only as the closed path grammar: existing `/workspace/NAME`, `/workspaces/NAME` or private `/tmp/prismpm-publication-capture-TOKEN/source`. Reject every overlap with `/candidate-input`, work, SDK, interpreter/tool or authority roots. Parent authorizes exactly that destination before actor creation. Docker-created intermediate directories must be root-owned and non-writable to UID1000; `/tmp` and `/workspaces` retain root-owned sticky tmpfs parents. For `/workspace/NAME`, the direct final source path is a mountpoint under the existing volume, not a writable symlink. Verify every ancestor/mountpoint with no-follow metadata and actual mountinfo before execution. If the runtime does not provide those protected parent semantics, reject that compiled path; do not create a same-UID writable parent as a fallback.

At both read-only source views, verify the same complete rows, source root identity and mount relation. No writable view may be present. Before and after execution check candidate rows, authority/ELF, normalized modes/link counts, metadata identities and protected parents; these are defense in depth around actual read-only mounts. Qualification must attempt same-UID symlink substitution, root/ancestor rename, hardlink creation, chmod and write-and-restore through both mounted views and every compiled-path ancestor. The candidate source path cannot be redirected to alternative bytes during the ELF's source reads. Neither mount restrictions nor metadata checks claim protection against a privileged daemon/host.

Stage transfer ends with real EOF before successful admission and before an execution actor exists. The execution actor receives only a closed run request binding the mounted descriptor, then follows the original response/retirement acknowledgement pattern; after returned evidence is independently verified, parent sends a descriptor-bound `retire` acknowledgement and closes stdin. Execution guest requires EOF, so trailing control bytes cannot produce accepted completion. A malformed control channel is a failed capture; it does not loosen the already completed source EOF check.

The additional actor/volume cannot silently double the original retirement budget. Ordinary staging retirement completes inside the execution portion of the outer deadline. Failure reconciliation handles at most two actor identities and two labelled volumes under the original 420-second reserve. Use a candidate cleanup adapter over `run_bounded` with each daemon call capped at 15 seconds and additionally clamped to the one absolute remaining deadline (legacy `docker()` has a fixed 30-second timeout and is not sufficient for this schedule). Predeclare a finite reconciliation sequence: at most 18 daemon operations ×15 seconds plus two attach retirement waits of at most 35 seconds gives 340 seconds, leaving 80 seconds of reserve margin. No retries or independent per-phase timeout resets. If an operation fails, attempt only safe remaining reconciliation within the deadline, retain both volumes and report uncertainty. On ordinary success remove execution actor first, prove absence, then remove authenticated input/work volumes; on any failed/uncertain capture remove only authenticated actors and retain the volumes. Missing/ambiguous ownership never authorizes removal. Focused real failure controls must establish this bound, including pending stage/execute creation and stage retirement failure; the latter must block execution actor creation.

Read-only SDK rootfs and exact mounts protect the installed root during ordinary actor operation. The mounted daemon socket is explicitly infrastructure authority; no network/container isolation or source-free product claim follows from it. The new route must preserve, not conceal, this existing scope limitation.
