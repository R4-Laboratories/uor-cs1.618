# Creative game evolution

User intent: expand the deployed self-improvement loop into the previously deferred creative/gameplay work and finish deployment autonomously.

Approaches considered: arbitrary model-written repository patches offer the broadest scope but no trustworthy automatic gameplay/credential boundary; adding more preset settings does not provide creative authorship. Chosen implementation: a typed program language for original procedural murals and bot decisions, compiled into real TypeScript, with optional GitHub Models authorship and built-in seeded synthesis. This is the implementer's choice under the user's autonomous execution instruction. It supports new programs, not unrestricted repository self-modification.

The mural language contains bounded normalized vector shapes, a two-site palette and line widths. It generates four wall-mounted original relay-station murals and a public gallery. Existing objective labels and collision geometry stay intact. Players can disable procedural artwork locally. Artwork is evaluated for palette/label contrast, site distinction, bounded coverage, actual browser rendering and unchanged protected scenery. Aesthetic quality is not objectively proved.

The tactics language contains at most 12 ordered boolean rules (depth at most 4, 64 expression nodes) and six allowed actions. It compiles to a pure decision function. Facts contain visible enemies, local equipment and public objectives; no hidden enemy position is supplied. The match still owns movement, damage, weapons and wins. New objective priorities must improve a training and held-out tactical scenario corpus, preserve invariants, and demonstrate real Match objective completion using Verdant and Prism Wasm. Player skill/balance and broad match win rate are not inferred from scenario performance.

A seeded synthesizer supplies useful new artwork and tactics without credentials. GitHub Models can supply a strictly validated program proposal from the public design brief; its token stays only in the author step. Provider failure is recorded and falls back to synthesis. No paid account or billing setup is assumed. Model output is data; no arbitrary JavaScript, imports, URLs, package installation or shell execution is accepted. Compiled code is deterministic and regenerable.

The existing admission Wasm consumes the same four host obligations, with family-specific meanings made explicit: fidelity means protected behavior/scenery invariants for creative changes, benefit means a declared task metric, bounds means domain/resource limits, checks means full game gates. A policy change does not expand the formal proof claim. Candidate content and source identities are bound in evidence. The publisher's allowlist expands only to the two generated modules; it still cannot edit its own gate. Existing state/history migrates without rewriting old hashes.

A public evolution studio displays the admitted artwork, recipe, tactics and evidence, with an original-versus-evolved preview. GitHub continues hourly evaluation, explicit Pages dispatch and deployment watching. Creative search has bounded attempts per source context and can settle; new public briefs/source changes reopen it. No promise of endless improvement.

Acceptance: runnable authoring, validated generated art/tactics, independent negative tests, real Wasm scenario evaluation, gallery screenshots inspected, complete application/browser/WebRTC gates, fresh branch review, observed GitHub creative admission and matching live Pages generation. If GitHub Models is unavailable, report that limitation with actual evidence while completing the functioning synthesis path.
