# Bounded numeric kernels

`BoundedNumeric.Float.mul32` and `mul64` consume raw IEEE bits and return `Option UInt32` / `Option UInt64`. The production export adds its generated `Result` failure effect. Both layers propagate to ABI status 2. Rounding is nearest/ties-even, underflow is gradual, zero signs are retained, the first NaN operand is quieted with its payload/sign preserved, and invalid zero-times-infinity returns positive canonical quiet NaN.

`Wide.multiply(UInt64, UInt64) -> Option Limbs` computes a full exact 128-bit product in four little-endian UInt32 fields. With B=2^32, every multiplication uses operands at most B-1. It calculates t0=a0*b0; t1=a1*b0+high(t0); t2=a0*b1+low(t1); t3=a1*b1+high(t1)+high(t2). Output limbs are low(t0), low(t2), low(t3), high(t3). The conservative cell bound is (B-1)^2+2(B-1)=2^64-1. No convolution column is accumulated unboundedly. Every multiply, addition, conversion and shift remains checked.

`Wide.right(Limbs) -> Option Limbs` shifts one bit across limbs. Each destination is its old limb divided by two, bit-or the next limb's low bit shifted 31 places. `Wide.low64(Limbs) -> Option UInt64` refuses nonzero high limbs. `Wide.length(Limbs) -> Option Int` returns the bit length (0..128) using 32 checked fixed-width shifts of the highest nonzero limb. `Wide.round(Limbs, Int) -> Option UInt64` shifts right with a guard and sticky bit and rounds once, or shifts left for a negative amount. An amount above 128 produces a mathematical zero directly; it is not an error fallback. The internal helper's left shift is used only with format-derived bounds. Exponents are checked-narrowed to UInt8/UInt16 before integer widening; the right-shift iteration count is checked-narrowed to UInt8 after the 128 bound. This avoids unnecessarily large bit-test widening certificates.

For binary64 finite nonzero operands, significands are at most 53 bits, the exact product at most 106 bits, and the scale is -2148..1942. The top-bit index is 0..105. The selected right-shift amount is -52..1074; values above 128 take the explicit underflow branch. Negative amounts are therefore shifts of at most 52, and the result is at most 53 bits. For binary32 the corresponding values are 24-bit significands, 48-bit product, scale -298..208, and shift -23..149. Rounding may add one to a value at most 2^p-1; the carry is normalized before packing. Exponents and all loop counters fit the unchanged SDK's signed/unsigned 64-bit target model.

These are reviewed mathematical bounds, not a universal source proof. `Bounds.limbAddBound` proves addition with explicit limb/carry Nat premises. `Bounds.cellAddBound` proves the linear cell-addition bound given the product bound as a premise. The nonlinear fact that two limbs' product satisfies that premise, the relation of these statements to every runtime branch, and universal IEEE correctness remain unproved. Production certificates prove preservation of the chosen source computation, including failures. Corpus conformance is a separate test claim.

Run `scripts/numeric/build.sh` followed by `scripts/numeric/test.sh`. The build generates the deterministic oracle corpus before SDK work and binds its digest during collection; no prior evidence directory is required. `NUMERIC_SDK_RUNNER` can point to a launcher for the exact model-pinned SDK. The default launcher uses the already cached read-only SDK root in this workspace, with a dedicated worktree mount. It never writes the earlier numeric-probe evidence area. `scripts/numeric/oracle.py` generates a deterministic exact integer/rational corpus; native hardware operations provide a second oracle for non-NaN results. The Wasm wrapper has no imports and marshals u64 values through JavaScript BigInt.

The `probe/` fixture checks a minimal record, checked operation, Option failure and small carry theorem in isolation. Its proofs and the full source/export evidence are retained separately. The earlier UInt32-to-Nat bound attempt expanded into bit-test branches under this patched SDK; its generated theorem and stopped-run receipt document that proof-language limitation.

Division roots `div32` and `div64` use the same raw-bit types, NaN policy, rounder and status ABI (op 2/3). Division by zero produces signed infinity except invalid 0/0; infinity/infinity is invalid; finite/infinity and zero/finite preserve the XOR sign on zero. Invalid operations produce positive canonical quiet NaN.

For each finite nonzero division, normalize both significands to 24 or 53 bits using a checked left shift, adjusting the bounded exponent difference by their original bit lengths. Normalize their ratio into [1,2). The initial quotient is 1 and remainder is numerator minus denominator. Each of exactly 25 or 54 steps doubles the remainder and quotient, conditionally subtracts the denominator and appends one quotient bit. Here 0<=r<d<=2^53-1, so 2*r<2^54 and the final quotient has at most 55 bits. Unsigned checked-subtract None is deliberately interpreted as r<d at that comparison; every other checked failure propagates. The remaining nonzero remainder jams the quotient's least bit. The common rounder shifts at least two bits, so that jammed bit supplies sticky information without double rounding. Underflow may increase the rounding shift; no huge numerator or denominator is constructed.

`Wide.from64` embeds a UInt64 into canonical limbs; `Wide.quotient32/64` are internal normalized-significand helpers with preconditions b>0 and b<=a<2*b. They return a quotient with remainder sticky information, not a generally rounded integer division. New linear theorems check the double-remainder bound, the reduced-remainder bound given its subtraction equation, and the quotient-step bound. They do not prove the complete runtime invariant or universal failure absence.

Task2 build evidence is separate in `artifacts/numeric-task2`; original Task1 bundles remain in `artifacts/numeric`. Collection uses the exact JSON result from the successful build, checks roots, current source/lock bytes and source identifiers, and never selects by mtime. The default oracle remains multiplication-only for old callers; the build requests `--include-division` explicitly.

Canonical PrismPM LCNF admission is **not claimed**. `compat/` and `compat-alternatives/` retain source-owned minimal diagnostics. Direct fixed checked arithmetic/nested steps compile and replay natively and in Wasm; fixed conversions retain generic dictionaries, helper specialization can produce unresolved `.spec_0` calls, signed comparisons are unresolved, and higher-order iteration escapes. Those pinned exporter issues and the eventual fixed exponent adaptation belong to Task2c. Current arithmetic uses the separately validated raw LexLean production backend with bounded mathematical Int and checked 64-bit target effects. No SDK, pin, guard or timeout is changed.
